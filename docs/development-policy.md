# Acrylic Pan for Arduino UNO Q — 開発方針

最終更新: 2026-08-21

この文書を UNO Q 版の技術判断における正本とする。旧 `acrylic_pan` の資料や実装と
矛盾する場合は、UNO Q 版については本書を優先する。旧 ML63Q2557 実装は比較基準と
移植元であり、UNO Q 版の性能上限ではない。

## 1. 製品目標

- KX134-1211 でアクリル板の振動を取得し、打撃位置・強度・確信度をリアルタイム推定する。
- 現行基準は400 x 300 x 5 mm、4 x 3の12領域分類とする。旧4 x 2・8領域は回帰比較用に残す。
- 最終目標は8分類に限定せず、連続 XY 座標、強度、未知／曖昧打撃の検出へ拡張する。
- 合成データの精度ではなく、別日に収録した実測データで再現することを合格条件とする。

## 2. UNO Q の役割分担

| 領域 | 担当 | 方針 |
|---|---|---|
| センサ取得 | STM32U585 | KX134 の SPI 取得、タイムスタンプ、リングバッファ、打撃候補切出しを決定論的に実行する |
| 学習・推論 | QRB2210 / Linux | Python で前処理と評価を行い、採用モデルを ONNX Runtime 等で推論する |
| 表示・発音 | QRB2210 / Linux | Web UI、ヒートマップ、音源、ログ保存を担当する |
| 連携 | Arduino Bridge | 取得イベントと制御コマンドを、版管理したメッセージ形式で交換する |

リアルタイム取得を STM32、計算量が大きく更新頻度も高い処理を Linux 側へ分離する。
モデル変更のたびにセンサ取得系を書き換えない。

## 3. AI モデル方針

### 3.1 ML63Q2557 の制約を継承しない

入力数と隠れノード数の合計、16 KB RAM、bfloat16、1隠れ層 ELM、Solist-AI
Simulator の出力形式は UNO Q 版の制約にしない。旧 128-64-8 ELM は回帰テスト用の
軽量ベースラインとして残すが、採用モデルの上限にはしない。

### 3.2 精度を優先して段階的に拡張する

1. ロジスティック回帰、勾配ブースティング、旧 ELM で再現可能な基準値を作る。
2. 生の3軸時系列を扱う 1D CNN / TCN / ResNet 系を比較する。
3. STFT や帯域エネルギーを扱うスペクトログラム CNN を比較する。
4. 必要なら時系列と周波数特徴の二枝モデル、分類と座標回帰の multi-task model を評価する。
5. 単体モデルで目標に届かない場合だけ ensemble や蒸留を検討する。

モデルの大型化そのものを目的にしない。実測のホールドアウト精度、座標誤差、確信度校正、
条件変化への頑健性が改善するときに限り複雑化する。

### 3.3 出力と評価指標

- 12領域分類: macro F1、balanced accuracy、混同行列、top-2 accuracy
- 連続位置: XY の中央値誤差、95 percentile 誤差、領域別誤差
- 強度: MAE と反復打撃に対する単調性
- 信頼性: calibration error、低確信度棄却後の精度、未知打撃の誤受理率
- 実行性: 前処理込み p50 / p95 latency、CPU・メモリ使用量、連打時の欠落率

精度比較は同じデータ版と同じ分割で行う。テストセットはモデル選択に使わない。

## 4. データ方針

詳細は [data-strategy.md](data-strategy.md) を正本とする。

- 旧 `acrylic_pan` リポジトリには実測元データがないが、元プロジェクトを開発したPCには
  実測元データが残っている。初期学習データセットはそのデータを移行して利用する。
- 現在の作業PCは元開発PCではないため、元データの取得・検査・学習は後続作業とする。
  それまでは配線、収録基盤、データschema、モデル枠組み、評価手順を先行する。
- 元データは直接編集せず、読取専用の原本として保全してからインポートする。
- 由来、ハッシュ、収録条件、ラベル定義、変換履歴を manifest に残す。
- 学習・検証・テストはイベントのランダム分割ではなく、収録セッション、日、打撃者、
  取付け直しの単位で分離する。
- ダミー／FEM合成データはパイプライン試験と事前検証に使えるが、実測精度の根拠にしない。
- 別製品・別センサ・別ラベルのデータを、検証なしに Acrylic Pan の教師データへ混ぜない。

## 5. ハードウェアと信号取得

- センサは KX134-1211 を継続使用し、独自コネクタから UNO Q への変換基板または
  ハーネスを用意する。
- 電源電圧、SPI 信号、GND、割込み線を実機導通で確認し、未確認ピンを推測で接続しない。
- サンプルレート、測定レンジ、LPF、軸方向、イベント長はデータ manifest に必須とする。
- 旧収録条件は初期再現条件として残すが、UNO Q 上でアンチエイリアスと精度を評価し、
  必要なら3軸化、窓長延長、複数解像度入力へ拡張する。

## 6. ソフトウェア品質

- センサ取得、イベント形式、前処理、モデル、ラベル定義に独立した version を付ける。
- 学習設定、乱数 seed、コード commit、データ版、評価結果を1 run単位で保存する。
- 前処理は学習と実機推論で同一実装または golden vector による同値検証を行う。
- 単体テストに加え、保存済みイベントから推論結果までの end-to-end 回帰テストを置く。
- 秘密情報、個人情報、出所不明データ、大容量の生データを通常の Git commit に含めない。
- 方針変更は理由、採用案、棄却案、影響範囲を本書または ADR に追記する。

## 7. 実装の優先順位

1. KX134 と UNO Q の安全な配線を確定し、3軸波形を欠落なく保存する。
2. 元開発PCから実測元データを移行・検証し、初期 dataset version を作る。
3. 同一分割で旧 ELM と強い非ニューラル基準を再評価する。
4. 1D CNN / TCN とスペクトログラム CNN を比較し、UNO Q 上の latency を測る。
5. 8分類に加え、XY・強度・確信度を multi-task 化する。
6. 別日・別打撃者・再取付け条件で評価し、モデルカードと再現手順を発行する。

## 8. 引継ぎ時の確認事項

- 本書と `docs/data-strategy.md` を最初に読む。
- `firmware/` は旧 ML63Q2557 の比較資料、`uno_q_app/` は現行実装として扱う。
- 旧 ELM の制約を、新しいモデルの要件として復活させない。
- 元開発PCから移行したデータも、受入検査と manifest 作成前には学習へ投入しない。
- 精度を報告するときは、データ版、分割単位、実測／合成、推論環境を併記する。
