Implementation roadmap

12領域の実測基盤から、
連続座標推定まで育てる。

STM32U585でKX134を確実に取り込み、QRB2210/Linuxで保存・学習・推論・表示を行います。現行400 × 300 × 5 mm・4 × 3構成を主対象とし、旧4 × 2構成を回帰比較に使います。

現在 — 12クラスUNO Q基盤移行元リポジトリの12クラスモデルと4 × 3パネル定義を統合済みです。センサ未接続状態では12代表入力を循環させ、Bridge、Linux推論、PC Web UIを検証します。

実装マイルストーン

M0

配線と電気条件を確定

独自コネクタの導通、電源、SPI、割込みを確認し、UNO Q GPIOとの対応表を固定します。

M1

12クラス自己診断

代表入力12件をSTM32から通知し、Linux推論と4 × 3 Web UIが全クラス一致することを確認します。

M2

3軸収録を成立

STM32のリングバッファで立上り前後を切り出し、Bridge経由でLinuxへ欠落なく保存します。

M3

初期datasetを移行

元開発PCの実測原本を保全・検査して現行12クラス形式へ移し、不足条件をUNO Qで追加収録します。

M4

モデルを拡張

旧ELM、1D CNN / TCN、スペクトログラムCNNを同一splitで比較し、UNO Q実機の精度とlatencyを測定します。

M5

multi-task推論と演奏UI

12クラス、XY、強度、confidenceを出力し、ヒートマップと発音へ接続します。

M6

頑健性とリリース

別日、別打撃者、センサ再取付け、弱打・強打・連打で評価し、データ版とmodel cardを公開します。

引継ぎ原則

  • 旧ML63Q2557のRAM、ノード数、bfloat16、ELM構造をUNO Qの制約にしない
  • 12クラスモデルは初期baselineであり、代表入力の一致率を実測精度と呼ばない
  • 初期学習データは元開発PCの実測原本を移行する
  • セッション・日・打撃者・再取付け単位で学習と評価を分離する
  • モデル、前処理、データ、ファーム、配線を別々に版管理する

全体判断は 開発方針、データ作成は 学習データ方針 を参照してください。
