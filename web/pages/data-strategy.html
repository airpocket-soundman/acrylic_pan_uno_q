09 / Dataset strategy

元開発PCの実測データを、
初期学習へ引き継ぐ。

旧リポジトリには実測データがありませんが、元プロジェクトの開発PCには元データが残っています。原本を保全して現行形式へ移行し、UNO Qで不足条件を追加収録します。

現在の制約このPCは元開発PCではないため、データ取得、検査、学習はまだ実行できません。移行待ちの間は配線、収録基盤、schema、importer、モデル枠組み、評価手順を先行します。

利用区分

元開発PCの実測初期dataset候補原本保全・受入検査・現行形式への変換後に利用
UNO Q追加実測条件補完別日・打撃者・再取付け・強弱を追加
旧repoのdummytest専用実測精度には使わない
IchiPing系別案件Acrylic Pan教師データには使わない

移行フロー

01

原本保全

場所、日時、容量、当時のコード版を記録し、変更せず複製してSHA-256を取ります。

02

互換性確認

センサ、軸、単位、ODR、range、LPF、窓長、座標、class IDを確認します。

03

品質検査と変換

欠損、飽和、重複、誤ラベルを検査し、現行session形式へ変換して対応表を残します。

04

versionと追加収録

group splitを固定して初期版を発行し、不足する独立条件をUNO Qで補います。

いま先行できること

  • 独自コネクタのピン配置とUNO Q GPIO対応
  • STM32U585の3軸SPI取得、リングバッファ、Bridge転送
  • session schema、validator、受入レポート
  • 旧ELM、1D CNN / TCN、spectrogram CNNの共通dataset API
  • group split、評価指標、model card、latency benchmark
  • 追加収録計画と品質flagの定義
現行保存形式data/raw/sessions/<session-id>/session.json, manifest.jsonl, manifest.csv, events/*.npz。大容量原波形は通常のGit commitへ含めず、manifest、hash、schema、変換コードを版管理します。

移行条件と管理規則の全文は 学習データの移行・追加収録・管理方針 を参照してください。
