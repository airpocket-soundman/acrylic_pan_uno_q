08 / Implementation roadmap

波形取得から始め、
連続座標推定まで育てる。

STM32U585でKX134を確実に取り込み、QRB2210/Linuxで保存・学習・推論・表示を行います。各段階を同じ実測hold-outで比較し、モデルを拡張しても再現性を失わない順序にします。

現在 — UNO Q基盤移行元開発PCの実測データは現在の環境から取得できないため、コネクタ確認、STM32側SPI収録、データschema、モデル枠組み、評価手順を先行します。

実装マイルストーン

M0

配線と電気条件を確定

独自コネクタの導通、電源、SPI、割込みを確認し、UNO Q GPIOとの対応表と変換基板版を固定します。

M1

3軸収録を成立

STM32のリングバッファで立上り前後を切り出し、Bridge経由でLinuxへ送り、現行session形式へ欠落なく保存します。

M2

初期datasetを移行

元開発PCの実測原本を保全・検査して現行形式へ移し、不足する日、打撃者、再取付け条件をUNO Qで追加収録します。

M3

baselineを再評価

旧ELMと非ニューラルモデルを同じsplitで評価し、精度、混同行列、XY誤差、latencyを記録します。

M4

深層時系列モデル

1D CNN / TCN、スペクトログラムCNNを学習し、候補をONNX等へexportしてUNO Q実機で測定します。

M5

multi-task推論と演奏UI

8クラス、XY、強度、confidenceを出力し、ヒートマップと発音へ接続します。曖昧打撃の棄却も実装します。

M6

頑健性とリリース

別日、別打撃者、センサ再取付け、弱打・強打・連打で評価し、データ版とmodel cardを含む再現可能なreleaseにします。

各マイルストーンのゲート

M0電圧・導通・SPI ID読出し未確認ピンを残さず、接続表を版管理
M1100イベント連続収録sequence欠落、破損、overrunが0
M2dataset manifest収録条件・hash・splitを再現可能
M3–M4固定hold-out比較同じ評価データと指標で改善を確認
M5UNO Q end-to-end前処理込みp95 latencyと連打欠落率を記録
M6独立条件評価精度表、model card、既知の限界を公開

引継ぎで迷わないための原則

  • 旧ML63Q2557のRAM、ノード数、bfloat16、ELM構造をUNO Qの制約にしない
  • 旧ELMは削除せずbaselineにするが、新モデル選定は実測精度で行う
  • 初期学習データは元開発PCの実測原本を移行し、UNO Qで不足条件を追加収録する
  • イベント単位の無作為分割ではなく、セッション・日・打撃者・再取付け単位で分離する
  • 合成データだけの精度を製品精度として報告しない
  • モデル、前処理、データ、ファーム、配線に別々のversionを付ける

全体判断は 開発方針、データ作成は 学習データ方針 を参照してください。
